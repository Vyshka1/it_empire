# CEO Review (понедельник, 40 минут)

Главный ритуал империи. Ведёт Chief of Staff, слово по очереди берут CPO, CTO, CFO/Strategy
и Founder Coach.

## Часть 1. Что произошло (10 минут)

```bash
python3 tools/empire.py week
python3 tools/empire.py commitments --all
python3 tools/empire.py capacity
```

Разбираем по фактам, а не по ощущениям:

- Какие из трёх результатов недели закрыты? Незакрытый результат разбирается: не хватило
  времени, оказался не той задачей или мы его избегали?
- Какие проекты реально продвинулись — и чем это подтверждается, кроме коммитов?
- Где потеряли время? (Расхождение `actual` и `planned` в capacity.)
- Какие решения зависли без ответа?

## Часть 2. Портфель (10 минут)

По каждому проекту CFO называет состояние вслух: **расход / актив / бизнес**.

Вопросы, которые задаются каждую неделю одинаково:

- Сколько людей поговорили с продуктом за неделю? Сколько пользуются?
- Какой следующий milestone и что его блокирует?
- Что мы делаем лишнего?

Если продукт в разработке дольше двух недель и пользователей ноль — CPO обязан поставить
вопрос «стоп development» ([`../agents/cpo.md`](../agents/cpo.md)).

## Часть 3. Основатель (5 минут)

```bash
python3 tools/empire.py skills --bottlenecks
python3 tools/empire.py stuck
```

- Остался ли bottleneck прежним? Если навык больше не мешает — снимаем флаг.
- Есть ли задача, которую избегали всю неделю? Разбираем причину, а не переносим.
- Если несколько недель подряд все результаты технические — это тема для CPO, а не
  для похвалы.

## Часть 4. Три результата следующей недели (15 минут)

```bash
python3 tools/empire.py week-plan \
  --result "meal-planner:..." \
  --result "price-base:..." \
  --result "founder:..." \
  --not-doing "..." --not-doing "..."
```

Правила, которые не обсуждаются:

1. **Ровно три.** CLI не примет два или пять.
2. Каждый результат — **завершённое состояние**, а не деятельность. «Поработать над
   архитектурой» не результат. «WeekPlan считает неделю без ручных правок» — результат.
3. Хотя бы один результат недели должен двигать продукт **к пользователю**, если в портфеле
   есть проект в стадии `product-development` и старше двух недель.
4. Список **НЕ ДЕЛАТЬ** обязателен и содержит то, что действительно хочется сделать.
   Пустой `not_doing` означает, что мы не выбирали.

Затем capacity на неделю:

```bash
python3 tools/empire.py capacity-set meal-planner=50 price-base=25 founder-skills=15 exploration=10
```

## Часть 5. Фиксация

- Всё, что основатель пообещала вслух → `commit-add`.
- Всё, что решили → `decision-add` (с условием возврата!).
- Всё, что стоило времени и научило → `lesson-add`.
- `python3 tools/empire.py render` — обновить `empire/STATUS.md`.
- Поле `review` у недели в `weeks.json` — две-три строки: что это была за неделя.

Ревью, после которого не изменилось состояние, — это разговор, а не ревью.
