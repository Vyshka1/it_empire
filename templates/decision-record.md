# Шаблон решения

```text
16.09.2026 — Meal Planner

Решили не добавлять новые функции до завершения унификации расчётов.
Причина: архитектурный долг создаёт каскадные ошибки.
Вернуться к решению после milestone X.
```

Запись:

```bash
python3 tools/empire.py decision-add \
  --project meal-planner \
  --what "Не добавлять новые функции до завершения унификации расчётов" \
  --reason "Архитектурный долг создаёт каскадные ошибки" \
  --revisit "Унификация расчётов завершена" \
  --tags scope,architecture
```

## Обязательные части

| Часть | Зачем |
|---|---|
| **Что решили** | Формулировка в повелительном виде, проверяемая со стороны |
| **Причина** | Через две недели причина забывается первой — а без неё решение выглядит произволом |
| **Условие возврата** | Решение без условия возврата либо вечное, либо будет нарушено молча |

Условие возврата — это **событие**, а не дата: «унификация расчётов завершена»,
«discovery по Price Base закончен», а не «через месяц».

## Жизненный цикл

```
active ──> closed        условие возврата выполнено, вопрос снова открыт
       └─> superseded    решение сознательно изменено новым решением
```

Забывание — это не переход. Решение, которое просто нарушили, остаётся `active`, и система
об этом напомнит в следующий раз.

## Как это работает через две недели

```
$ python3 tools/empire.py decision-check "давай добавим AI-подбор меню"

МЫ ОБ ЭТОМ УЖЕ ДОГОВАРИВАЛИСЬ
  D-001 (2026-09-16): Не добавлять новые функции в Meal Planner до завершения унификации
       Причина: Архитектурный долг создаёт каскадные ошибки
       Условие возврата: Унификация расчётов завершена

  Условие возврата уже выполнено — или мы сознательно меняем решение?
```

Оба ответа нормальные. Ненормально — не заметить, что решение было.

Сознательная смена:

```bash
python3 tools/empire.py decision-supersede D-001 \
  --what "Разрешаем новые функции Meal Planner" \
  --reason "Унификация завершена, каскадные ошибки больше не воспроизводятся"
```
