# Шаблон плана недели

```text
WEEK 38

#1 Meal Planner
Закончить архитектурную стабилизацию WeekPlan.

#2 Price Base
Провести discovery и определить MVP.

#3 Founder
Разобраться с deployment настолько,
чтобы самостоятельно контролировать выкладку.

НЕ ДЕЛАТЬ:
— новый дизайн Meal Planner;
— новые рецепты;
— Signal до окончания discovery Price Base.
```

## Почему три

Три результата — это то, что человек с ограниченным временем может закрыть и запомнить.
Двадцать пять todo — это способ не выбирать: в конце недели половина сделана, и непонятно,
была ли неделя успешной. `week-plan` в CLI не примет другое число.

## Почему «НЕ ДЕЛАТЬ» так же важно

Опасность не в отсутствии идей, а в их количестве. Список `not_doing` содержит то, что
действительно хочется сделать на этой неделе — иначе он бесполезен. «Не лететь на Марс»
в него не пишут.

Три источника строк для `not_doing`:
1. Действующие решения (`empire decisions`).
2. Идеи из бэклога, которые тянет начать.
3. То, что провалилось в приоритете на CEO Review.

## Проверка формулировки

Результат недели — завершённое состояние, а не деятельность.

| Плохо | Хорошо |
|---|---|
| Поработать над архитектурой WeekPlan | WeekPlan считает неделю без ручных правок |
| Подумать про Price Base | Поговорила с тремя людьми, MVP описан одной страницей |
| Разобраться с деплоем | Выкатила изменение сама, без посторонней помощи |

Если по формулировке нельзя однозначно сказать «сделано / не сделано» — это не результат.

## Запись

```bash
python3 tools/empire.py week-plan \
  --result "meal-planner:WeekPlan считает неделю без ручных правок" \
  --result "price-base:Поговорила с тремя людьми, MVP описан одной страницей" \
  --result "founder:Выкатила изменение сама" \
  --not-doing "Новый дизайн Meal Planner" \
  --not-doing "Signal — до окончания discovery Price Base"
```
