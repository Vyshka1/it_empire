# Шаблон проверки навыка

Проверка проводится **только** по навыку, помеченному `bottleneck: true`. Тесты «на общее
развитие» запрещены: они тратят единственный невозобновляемый ресурс.

## Форма: кейс, а не вопросы

Плохо: «что такое unit-экономика?»
Хорошо: настоящая ситуация из её портфеля, где нужно принять решение и защитить его.

```text
КЕЙС · PRODUCT/prioritization

Ситуация:
В бэклоге Meal Planner две задачи.
A. Переписать расчёт КБЖУ на общий движок — 2 дня, уберёт три известных бага,
   архитектурно правильно.
B. Экспорт списка покупок в заметки телефона — полдня, просили оба человека,
   которым ты показывала продукт.

Вопрос:
Что делаешь на этой неделе и почему? Что произойдёт, если сделать наоборот?

Что проверяем:
отличает ли она технически интересную задачу от коммерчески важной,
и умеет ли назвать цену отложенного решения.
```

## Оценка

| Уровень | Что означает |
|---|---|
| 0 | не сталкивалась |
| 1 | знает, что это существует |
| 2 | может сделать вместе с Claude по шагам |
| 3 | может поставить задачу и проверить результат |
| 4 | может принять решение самостоятельно и отвечать за него |
| 5 | может спроектировать с нуля и научить другого |

Для большинства технических навыков **цель — уровень 3, а не 5**. Основателю не нужно уметь
писать всё самой; ей нужно уметь поставить задачу и проверить результат. Уровень 4+ имеет
смысл там, где решение нельзя делегировать: архитектура, продукт, деньги.

```bash
python3 tools/empire.py skill-set PRODUCT/prioritization --level 3 --bottleneck no \
  --evidence "Кейс от 16.09: выбрала B, назвала цену отложенного A"
```

## После проверки

- Уровень достаточный → снять `bottleneck`, вернуть часы в продукт.
- Уровень недостаточный → назвать **одно** конкретное действие (не курс): «на этой неделе
  разбери приоритет бэклога Meal Planner по этой схеме и защити результат».
- Навык оказался не bottleneck → снять флаг и извиниться за потраченное время. Ошибка коуча,
  а не основателя.
